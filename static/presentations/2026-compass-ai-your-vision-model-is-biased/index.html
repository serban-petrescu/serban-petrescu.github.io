No single flag ever punishes a student on its own.

  • Precision is the top KPI: of what we flag, how much a human agrees with. 0.90 hard floor, 0.95 goal
  • Recall second: of what happened, how much we caught
  • We would rather a kid cheat successfully than accuse one wrongly
  • Timeline, walk it once: 4 events, we caught 3, one false alarm. 0.75 and 0.75, both fail
  • Latency: under two minutes
  • We set these mid-build. Setting them on day one would have saved us pain

We build gold ten seconds at a time

  • Every week brought a new model and a new idea. Every demo looked good.
  • Picking needs a harness: run every idea against the same sessions, scored the same way.
  • Pre-trained or not: a quality claim needs a figure behind it.

We annotate in 10-second blocks to keep it simple. In around 13% of them, humans could not decide on the first pass.

  • Measuring needs a gold dataset: consented, representative sessions, hand-annotated
  • 10-second chunks, per behavior: present, clean, or undecided
  • Undecided = even a human can't tell, so the model isn't penalized either way
  • ~13% undecided at first. Built months in: should have been week one

Disagreement was the point: every divergence told us which rule to write.

  • Blind exercise: several of us annotated the same session
  • Mostly agreement, but there are ten-second blocks where all three of us disagree
  • Don't walk through each annotator
  • Bias 1, definition bias: one engineer wrote the rules the way they made sense to him. The disagreement exposed the assumptions baked in
  • Forcing alignment removed biases from the definitions before any model got blamed

Ask a model every 30 seconds whether anything happened, and it will tell you something did.

  • Attempt 1, 2025: Gemini Live on Gemini 2.0, the tech behind a call with Gemini. Big smart model, everything streamed in
  • JPEGs and audio in, answers back in real time
  • Built for conversation: it only speaks when spoken to
  • So we nudged it: a system message every N seconds asking "is the student cheating?"
  • Bias 2, bias to action: every nudge got an answer. False positives everywhere
  • Never left engineering, never measured. Latency = nudge cadence: 5s or 30s

Blind to motion, deaf to audio, and $1,000 per student per month.

  • Diagnosis: Gemini is dumb, use the best model. Claude Sonnet, 2025
  • Frames only: 5 screen + webcam frames per call, plus context frames
  • Context because behaviors are actions: a single still judges nothing
  • Bias 3, input bias: no audio. A parent dictating answers never happened
  • Each call carried the previous verdicts as memory, so calls ran in sequence
  • 1 minute took 5 to process. End of a one-hour session: feedback hours late
  • Precision ~0.70, recall 0.20, and about $1,000 per student per month

Attempt 3: audio doubled recall and hid the precision gap

0.40

2x

We shipped it everywhere, and our own number was wrong by a factor of eight.

  • Inputs matter, so back to Gemini, but Flash, not Live: real video, audio, motion
  • We sent the 10-second chunks exactly as LiveKit gave them
  • One prompt did everything
  • Bias 4, design bias: we carried Sonnet's rolling window over to video without asking whether a minute of video already has enough context. One line, move on
  • That sequence plus memory is what makes latency compound: 5x on Sonnet, still ~2x here
  • Precision close to the bar on our gold set
  • We shipped it because a human reviewed every finding before the student saw it. The reviewer covered the precision gap

No human would ever say a student is drinking from their phone.

  • New cohorts landed: homeschoolers, kids outside the Austin campus. Reviewer flags exploded
  • Measured: ~0.10 precision in production vs ~0.80 on gold. The prompt was overfitting our gold set
  • Worst case: "holding a phone and drinking from it". This is Markus re-enacting it
  • No human, smart or not, says that. It falsified the premise
  • Not about how intelligent the model in the middle is. We were biasing it
  • Reproduced in isolation; a paper (footnote) later found the same

Prompting harder made it worse

Every prompt line fitted the prompt harder to the videos we had handpicked.

  • Bias 5, prompt bias: the question makes the eyes look for the thing
  • "Is this person holding a phone?" alone: 41% wrong on our sessions
  • The prompt grew to 400 lines of don't-detect-this, only-focus-on-that, one rule per false positive
  • Say the word: that loop is overfitting, with prompts instead of weights. The gap to production kept growing
  • Describe first, classify after: the hallucinations mostly go away. On Gemini 3 models, near zero
  • And the input: the webcam was 10% of the pixels we sent. Fixing that alone: 67% to 40%

  • Back to fundamentals: single responsibility, architect against bias
  • Keep vision dumb: one window, one simple question. No memory, no test rules
  • Facts separate from enforcement: deterministic code applies the rules
  • One smart model at the end, over text only: patterns across the session
  • Close to classical computer vision, just multimodal
  • Once we understood the problem, the rebuild took a couple of weeks

Separating the eyes from the judge cleared the gate

The model that decides never sees a pixel.

  • Two steps. The narrator describes neutrally; the word phone never appears
  • The classifier reads only the text and answers booleans: device? help? only the test on screen?
  • Raw account of what happened, decoupled from the judgment
  • A paper published the same split after we shipped it

Stateless everywhere, except one place built to remember.

  • The window graph: 60-second windows (worked best), narrators feeding classifiers. No memory to carry a bias forward
  • Consolidator: deterministic, merges all findings and data sources, enforces the rules. The only stateful part
  • 0.95 precision, 0.90 recall, on gold and on live traffic reviewed by annotators. Round numbers on purpose, if asked: ~93 annotators, ~96 gold, recall ~91
  • Burned once, so production review is part of the measurement
  • Good enough that we removed the human in the middle: students see findings directly
  • Latency: two minutes, constant

62 models auditioned for one job

Every new model gets a blind check first: what do you see? what do you hear?

  • Now we can shop for models: 2.5 Flash to 3.1 Flash Lite
  • One sentence on the funnel: every week an AI auditions new models, cheapest one above the floors wins
  • Challenger: Ling for vision, TypeSafe Jev for the yes/no classifier
  • Bias 6, the "worked before" bias: we sent LiveKit's HLS as-is. Gemini 2 read it unofficially; Gemini 3 silently dropped the audio
  • So Gemini 3 looked worse. It wasn't, it was deaf
  • Now every audition starts with a capability check. "Worked before" is a bias too

Cheaper and better are the same direction

The cheapest system we ever ran is the most accurate one. That is not a coincidence.

  • Don't read every point: start and end only
  • Sonnet: ~$1,000 per student, $3.4M a month at today's scale
  • Window graph: $26, under $100k a month. Ling + Jev may reach ~$12
  • The most expensive systems were the worst ones

Six rules we would follow if we started again

  1. Build gold before you build anything: annotate to align, and let the disagreements write the rules. Bias 1
  2. Set the bar before the architecture: precision is a gate, recall a target, latency a constant.
  3. Keep it simple: no silver bullets, however strong the launch benchmarks looked. Bias 2
  4. The question shapes the answer: keep rule words away from the eyes, and your own bias out of the dataset. Bias 5
  5. Make the pipeline dumber: deterministic where code can decide, one binary question where it cannot. Bias 4
  6. Measure the input before you judge the model: check what it actually receives, and what it perceives. Bias 3 Bias 6

Every mistake was a bias we put there ourselves. That is the good news: so were all the fixes.

  • 1. Gold and definitions before anything
  • 2. Set the bar before the architecture
  • 3. No silver bullets: I've said it about microservices and blockchain, AI got me anyway
  • 4. The question can carry the bias: prompt, dataset, definitions
  • 5. Start dumb, add complexity; don't start complex and strip it
  • 6. Check the model actually gets the input you think you send
  • The biases weren't the model's. They were ours, which is why we could fix them
  • Fixing was fast, understanding was slow: 18 months down wrong paths, a couple of weeks to build and ship the window graph

  • Narrator still sees pixels, why no phone? Nothing in its prompt points at a phone. When it errs, the error is text we can read and re-run
  • When is one big model right? Reasoning over text. It breaks when perception and a loaded rule share one prompt: split what happened from what it means
  • Why don't the labs fix it? The prior is a feature on average. Vo et al.: 17% for the model vs 95% for a probe on the same encoder; "only answer from what you see" bought under 2 points
  • Is my prompt overfitted? If every line fixes one failure you saw, yes. Test on a different population, or delete half and re-run
  • How much gold? Coverage and real disagreement beat volume. Then the ladder: gold, 50 reviews, 200 reviews
